# PROMPT ДЛЯ CODEX: Обновление «Прогрев прокси + score-gate + прогрев аккаунтов» (С НУЛЯ)

## 0) Контекст проекта

Проект: **ETIX CHECKER** (Python, Playwright, CLI + CustomTkinter GUI).  
Цель проекта: проверка доступности билетов по списку шоу (`data/shows.csv`) через пул прокси (`data/Chezile.csv`) с формированием `report.csv`.

Ключевые файлы:
- `app_core.py` — основная логика проверки.
- `gui_app.py` — GUI.
- `cli.py` — CLI.
- `features/proxy_state.py` — persistent storage state по прокси.
- `features/warmup.py` — базовый warm-up (частично реализован).

Важно: часть доработок уже была начата, но после краша системы обновление осталось **незавершенным**.

---

## 1) Общая задача

Нужно **полностью завершить** обновление по прогреву прокси, которое включает:
- warm-up сайтов перед стартом проверки;
- persistent storage state по прокси (между запусками);
- проверку score через `https://antcpt.com/score_detector/` и старт основной проверки только при достаточном score;
- отображение прогресса прогрева в GUI;
- отдельный режим «Прогрев аккаунтов» (массовый прогрев профилей/прокси без основной проверки шоу).

Код должен быть:
- PEP 8;
- поддерживаемый;
- модульный (новый функционал — в новых файлах/папках, с аккуратным подключением к текущей логике);
- без поломки существующей логики check_shows/manual mode/report.

---

## 2) Источник требований (суммарно по истории чата)

Ниже финальные требования пользователя, которые нужно реализовать:

1. Добавить файл `data/warmup_sites.txt`, куда пользователь добавляет сайты (1 сайт = 1 строка).
2. При старте проверки делать warm-up в **каждом контексте/вкладке** (ориентир: 12 вкладок, но фактически использовать текущее значение `TABS_COUNT`).
3. В каждом контексте открыть **3 случайных ссылки** из `warmup_sites.txt` (без дублей в рамках контекста, если хватает ссылок).
4. Это делается **один раз в начале прогона** (до первого шоу), затем скрипт идет по обычной логике шоу.
5. Должен быть persistent storage state по прокси, чтобы эффект прогрева сохранялся между запусками.
6. После warm-up переходить на `https://antcpt.com/score_detector/` и считывать `Your score is:`.
7. Основную проверку шоу запускать только если score у прокси достаточный (**>= 0.7**).
8. В GUI, в зоне результатов/статусов, выводить строки вида:  
   `Proxy 1 - 0.4`, `Proxy 2 - 0.7`, и т.д.
9. Добавить отдельную функцию «Прогрев аккаунтов»:
   - запуск в скрытом режиме;
   - на каждом профиле открывать 3-7 сайтов;
   - на каждом сайте делать скролл 3-7 секунд;
   - работать батчами по 3 профиля одновременно, пока не будут прогреты все (обычно 12).
10. Не делать шаринг “живых cookies” между устройствами (каждое устройство хранит свое локальное состояние).

## 4) Что нужно доделать (обязательный scope)

### 4.1 Warm-up sites файл

Сделать надежную поддержку файла:
- путь: `data/warmup_sites.txt`;
- если файла нет — создать шаблон;
- пропускать пустые строки, комментарии (`#`), невалидные URL;
- убрать дубли.

### 4.2 Полный warm-up flow в основном прогоне

В `check_shows()`:
- выполнять warm-up только один раз перед первым шоу;
- на каждой вкладке открыть N random URL (`warmup_urls_count`, минимум 1, дефолт 3);
- после этого на каждой вкладке получить score с score detector;
- если score < 0.7 (или не удалось определить):
  - прокси считать непригодным для старта основной проверки;
  - заменить прокси на другой и повторить warm-up + score-check для этой вкладки;
  - добавить ограничение по числу попыток замены (например 3-5), чтобы не зациклиться.
- если не удалось собрать достаточное число вкладок с score >= 0.7:
  - завершать запуск понятной ошибкой (в GUI/CLI);
  - не переходить к проверке шоу.

### 4.3 Score parsing

Сделать устойчивый парсер score:
- основной источник: текст страницы (`innerText`) с поиском шаблона `Your score is: X`;
- X как float в диапазоне [0.0, 1.0];
- если не найдено — `None`.

### 4.4 GUI интеграция warm-up событий

В `gui_app.py`:
- прокинуть `warmup_enabled` и `warmup_urls_count` в `app_core.check_shows(...)`;
- реализовать `on_event` callback и очередь для warm-up событий;
- в `_poll_queue` обработать тип событий warm-up;
- визуально выводить строки статуса:
  - `Proxy 1 - 0.8` (или `Proxy 1 - n/a` при неудаче);
  - можно добавлять суффикс `pass/fail`.
- реализовать метод `open_warmup_sites()` для кнопки `Open warmup_sites.txt`.

### 4.5 Отдельная функция «Прогрев аккаунтов»

Добавить отдельный режим/кнопку в GUI: `Прогрев аккаунтов`.

Требования:
- не запускать проверку шоу;
- прогревать только прокси-профили;
- батчи: по 3 профиля одновременно;
- для каждого профиля:
  - 3–7 случайных URL из `warmup_sites.txt`;
  - переход на URL + скролл 3–7 секунд;
  - сохранить storage state;
- после завершения батча закрыть его контексты и перейти к следующему батчу;
- вести прогресс в GUI (`Прогрето X/Y`).

Примечание по “скрытому режиме”:
- для надежности использовать headless-режим в этом специальном потоке прогрева;
- основную проверку не менять этим флагом глобально.

### 4.6 Режим “Use same proxies” и cookies

Сохранить текущую логику:
- когда включено “Использовать те же прокси”, использовать сохраненный порядок последних рабочих прокси;
- bad-прокси из прошлого/текущего прогона исключать;
- storage state для таких прокси сохранять и повторно использовать;
- без лишней очистки cookies/state, если state уже есть.

## 8) Критерии приемки (Acceptance Criteria)

Считать задачу завершенной, если:

1. При включенном warm-up:
   - читается `data/warmup_sites.txt`;
   - прогрев выполняется один раз перед первым шоу;
   - по каждому прокси отображается score в GUI.
2. Основной прогон не стартует для вкладки/прокси, пока score < 0.7.
3. Прокси со слабым score автоматически заменяются (в рамках retry-limit).
4. После успешного прогона сохраняются state-файлы по прокси.
5. `Use same proxies` использует порядок last good proxies и state.
6. Кнопка `Open warmup_sites.txt` работает и открывает файл.
7. Функция `Прогрев аккаунтов` отрабатывает батчами по 3 до конца пула.
8. Полуавто-режим первого шоу и текущая логика корзин/captcha не сломаны.
9. `report.csv` продолжает формироваться корректно.

## 9) Smoke-тесты после внедрения

### Тест A: Warm-up + score-gate
- Включить warm-up, `warmup_urls_count=3`.
- Проверить, что в GUI выводятся `Proxy N - <score>`.
- Проверить, что вкладки с score < 0.7 заменяются.
- Проверка шоу стартует только после набора подходящих прокси.

### Тест B: Same proxies
- Сначала выполнить успешный прогон.
- Повторный запуск с “Использовать те же прокси”.
- Убедиться, что используется тот же порядок (кроме bad-прокси), state подхватывается.

### Тест C: Account warmup mode
- Запустить «Прогрев аккаунтов».
- Проверить батчи 3/3/3/3 (при 12 профилях).
- По завершению есть сохраненные state файлы.

### Тест D: Regression
- Запустить полуавто режим первого шоу.
- Проверить, что ручное решение капчи работает как прежде.
- `report.csv` создается без `url`.
