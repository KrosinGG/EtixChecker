## 🛠 Зафиксированные ошибки и решения:

### [2026-08-21] Безопасное обновление Inline-сообщений Telegram (aiogram 3.x)
- **Контекст / Ошибка:** При повторном клике на Inline-кнопку без изменения текста или клавиатуры aiogram выбрасывает `TelegramBadRequest: Bad Request: message is not modified`.
- **Причина:** Telegram Bot API запрещает редактировать сообщение, если новое содержимое и разметка полностью идентичны текущим.
- **Решение:** Создана утилитарная функция `safe_edit_message(event, text, reply_markup)`, перехватывающая `TelegramBadRequest` с проверкой подстроки `"message is not modified"` и подтверждающая callback query без падения приложения.

### [2026-08-21] Группировка слотов и фильтрация доставки в Combinatorics Engine
- **Контекст / Ошибка:** При тестировании одиночных ордеров наличие хотя бы одного билета с `UPS`/`Will Call` в объединенном слоте исключало всю группу.
- **Причина:** Логический слот `OrderGroup` объединяет все билеты с идентичными `(Venue, Event Name, Date, Time, Section, Row)`. Если в тесте генератор создает ордера с одинаковыми дефолтными значениями, они схлопываются в один неделимый слот.
- **Решение:** В доменной модели `OrderGroup` проверка `has_restricted_delivery` валидирует весь неделимый слот целиком, а в тестовых фикстурах и боевых сценариях разные ордера разграничиваются по их физическим параметрам (секция/ряд/место).

### [2026-08-21] Парсинг списков в pydantic-settings из .env (DotEnvSettingsSource)
- **Контекст / Ошибка:** `pydantic_settings.exceptions.SettingsError: error parsing value for field "ADMIN_IDS" ... JSONDecodeError`.
- **Причина:** Если поле типизировано строго как `list[int]`, `pydantic-settings` пытается распарсить строку из `.env` через `json.loads()`, что падает на строках с плейсхолдерами или запятыми без скобок.
- **Решение:** Объявлять тип поля как `list[int] | str` и применять `@field_validator(mode="before")` для безопасного извлечения числовых идентификаторов.

### [2026-08-21] HTTP/2 поддержка в httpx.AsyncClient и пакет h2
- **Контекст / Ошибка:** `Using http2=True, but the 'h2' package is not installed. Make sure to install httpx using 'pip install httpx[http2]'`.
- **Причина:** Библиотека `httpx` требует дополнительный пакет `h2` для работы протокола HTTP/2. Если флаг `http2=True` включен без установленного `h2`, `httpx` выбрасывает исключение.
- **Решение:** Добавлен пакет `h2` (и `httpx[http2]`) в `requirements.txt`, а в `crm_client.py` реализована проверка доступности `h2` с мягким откатом на HTTP/1.1 при отсутствии пакета.

### [2026-08-21] Авторизация в ASP.NET Core CRM (BetterTickets) и ложное срабатывание куки
- **Контекст / Ошибка:** Бот возвращал "Нет доступных новых заказов в пуле", в логах: `Session expired while requesting ... Re-authenticating... Fetched 0 raw orders`.
- **Причина:** Проверка `len(client.cookies) > 0` считала сессию авторизованной сразу после `GET /account/login` (из-за установки технической куки Antiforgery), даже если `POST /account/login` не завершился успешно. В результате `GET /buying/orders` редиректился обратно на логин-страницу, возвращая 0 заказов.
- **Решение:** Форма авторизации строго подогнана под контракт BetterTickets (`Login`, `Password`, `RememberMe`, `__RequestVerificationToken`), а валидация успешного входа проверяет наличие аутентификационной куки `Identity` и отсутствие редиректа на `login`. При ошибке авторизации выбрасывается явное понятное уведомление в Telegram.
